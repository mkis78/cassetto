# Base A (Sidebar, Undo, Open With) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Cassetto a Finder-style sidebar (floating panel / icon rail / optional tiles), Cmd+Z undo for every file operation including restore from Trash, and an Open With submenu, on macOS and Linux.

**Architecture:** OS-specific behaviour lives in `src/main/platform/{trash,volumes,openWith}.ts`, each exporting the same functions with a darwin and a linux branch; pure parsers sit beside them and are unit-tested. Undo is recorded in main around the single `files:op` handler (`src/main/undo.ts`). The sidebar is one React component left of dockview in `App.tsx`, persisting in `AppState`.

**Tech Stack:** Electron 45, React 19, dockview-react 8, lucide-react, vitest 5, `osascript` (AppleScriptObjC) on macOS, `gio` on Linux.

**Spec:** `docs/superpowers/specs/2026-11-17-base-a-design.md`

## Global Constraints

- Platforms: macOS and Linux. Windows is not a target. No native Node modules; macOS APIs only through `osascript` with AppleScriptObjC (JXA crashes on out-parameters, exit 139).
- No feature may need Full Disk Access, Finder automation permission, or Finder itself.
- A capability missing on a platform hides its UI entry; it never breaks the rest.
- UI strings: `t('<Italian>')` / `tx()`, English added to `src/shared/locales/en.ts`. Commit messages in English, no Claude trailers.
- Undo never overwrites: a step whose target name is taken or whose source is gone is refused and reported, the rest continue.
- Undo stack cap: 50 records, in memory only. Not undoable: `delete` (permanent), remote `move`/`copy` with `replace: true`.
- Paths go to `osascript`/`gio`/`open` as argv, never interpolated into script text.
- Shortcuts: sidebar toggle Cmd+Alt+S (macOS) / Ctrl+Alt+S (Linux); undo Cmd+Z / Ctrl+Z in a Files panel only.
- Favourite colours: the six `TAB_COLORS`; default the accent.

## Review Focus

- Undo of a trash whose original name has since been reused → that item refused with "Esiste già", nothing overwritten (Task 2 test `undo trash refuses when name is taken`).
- Undo of a trash after the Trash was emptied → item reported as missing, others restored (Task 2 test `undo trash reports an item gone from the trash`).
- Remote undo of a copy/mkdir after the user changed it → refused, nothing deleted (Task 2 test `remote undo refuses a changed copy`).
- A favourite whose folder was deleted or whose disk was unmounted → shown dimmed, click shows the error in the panel, no crash (Task 5 manual check).
- File names with spaces, quotes, accents or newlines through `osascript`/`gio` → handled (Task 1 test `trash on darwin keeps odd names`, Task 6 test `parseGioMime keeps names with spaces`).

### Task 2: Undo records and the undo run

**Files:**
- Create: `src/main/undo.ts`
- Modify: `src/main/index.ts` (`files:op`, new `files:undo`), `src/shared/types.ts`
- Test: `test/undo.test.ts`

**Interfaces:**
- Consumes: `Trashed`, `runOpLocal` result `trashed` (Task 1); `runOpRemote`, `sshRun`, `shQuote` (`src/main/ssh.ts`).
- Produces (in `src/shared/types.ts`): `export type UndoResult = { label: string; failed: { path: string; error: string }[]; dirs: string[] } | null` (`dirs`: folders to refresh; null = nothing to undo).
- Produces (in `src/main/undo.ts`):
  - `type Step = { kind: 'move'; from: string; to: string } | { kind: 'trash'; path: string } | { kind: 'removeIfSame'; path: string; stamp: string }`
  - `type UndoRecord = { host: string | null; label: string; steps: Step[] }`
  - `inverseOf(host: string | null, op: FileOp, failed: Set<string>, trashed: Trashed[], stamps: Map<string, string>): UndoRecord | null`
  - `class UndoStack { push(r: UndoRecord): void; pop(): UndoRecord | undefined; peek(): UndoRecord | undefined }` (cap 50, drops oldest)
  - `runUndo(r: UndoRecord, deps: { local: (op: FileOp) => Promise<OpResult & { trashed: Trashed[] }>; remote: (host: string, op: FileOp) => Promise<OpResult>; stamp: (host: string, path: string) => Promise<string | null>; remove: (host: string, path: string) => Promise<OpResult> }): Promise<NonNullable<UndoResult>>`
  - `stampScript(path: string): string` — remote shell that prints a stamp:
    `find -- P -exec sh -c 'stat -c "%n %s %Y" -- "$@" 2>/dev/null || stat -f "%N %z %m" -- "$@"' _ {} + | sort` with `P` shell-quoted.

- [ ] **Step 1: Write failing tests** in `test/undo.test.ts` (pure `inverseOf`, plus `runUndo` against temp dirs with the real `runOpLocal` and a fake trash that moves into a temp bin):
  - `inverseOf` rename `a→b` → steps `[move b→a]`, label `Rinominato «a»`.
  - move of 3 items with one failed → two `move` steps back, label `Spostati 2 elementi` (`t('Spostati {n} elementi', { n })`); a single item → `Spostato «a»` (`t('Spostato «{name}»')`). Same pattern for the other ops: `Creato «{name}»`, `Copiati {n} elementi` / `Copiato «{name}»`, `Spostati nel Cestino {n} elementi` / `Spostato nel Cestino «{name}»`.
  - move with `replace: true` locally → `move` back plus a `move` from the replaced item's `trashed` path to its original; remote with `replace` → `null`.
  - local touch/mkdir/copy → `trash` steps; remote → `removeIfSame` with the stamp from `stamps`.
  - trash → `move` from each `trashed` to `path`; item without `trashed` → still a step that will report `Non trovato nel Cestino`.
  - delete → `null`.
  - `undo trash refuses when name is taken`: trash `x`, create a new `x`, runUndo → failed `[{ path: x, error: 'Esiste già' }]`, new `x` untouched.
  - `undo trash reports an item gone from the trash`: trash `x`,`y`, delete `x` from bin, runUndo → `y` restored, `x` failed `Non trovato nel Cestino`.
  - `remote undo refuses a changed copy`: run via `deps.stamp` returning a different stamp → failed `Modificato dopo l'operazione: non rimosso`, `deps.remove` never called.
  - `UndoStack` keeps the last 50.

- [ ] **Step 2: Run** `npx vitest run test/undo.test.ts` → FAIL.

- [ ] **Step 3: Implement `src/main/undo.ts`.** `move` steps run as `rename` ops (local `runOpLocal`, remote `runOpRemote`), which already refuse an existing name. `trash` steps batch into one local `trash` op. `removeIfSame`: compare `deps.stamp` with the recorded stamp, equal → `deps.remove` (remote `delete` op), else refuse. Steps run in reverse order of recording. `dirs` = parent folders of every path touched.

- [ ] **Step 4: Wire `index.ts`.** One `UndoStack`. `files:op`: run as today; for a remote `mkdir`/`touch`/`copy` that succeeded, take stamps via `sshRun(host, stampScript(p))` for each created path before building the record; push `inverseOf(...)` when not null. `handle('files:undo', ...)` pops and runs, returns `UndoResult`; `handle('files:undoLabel', () => stack.peek()?.label ?? null)`.

- [ ] **Step 5: Run** `npm test` → PASS.

- [ ] **Step 6: Commit** `feat: undo for file operations in main`
